## The two sets are very different

| | 1978–2000 files | 2000–2025 files |
| --- | --- | --- |
| Source | MySchool API (HTML + `is_correct`) | Flattened text export |
| Answer key | ✅ Yes, for every question (3 have two options marked) | ❌ None |
| Formatting | ✅ Superscripts and subscripts kept as HTML | ❌ Lost in the question text (`3x 2 - x 3` should be `3x² − x³`); LaTeX in maths options is fine |
| Diagrams | 561 image **file names** (not URLs), which must be downloaded and hosted | 17 "diagram present, URL not verified" placeholders and no real images; about 470 questions mention a diagram that isn't there |
| Comprehension passages | ✅ Attached (430 English questions) | ❌ About 370 questions mention a passage that isn't included |
| Options | 4, or 5 (A–E) for older papers | 4 (49 Chemistry questions have an E) |

**Biggest single win: re-run the 1978–2000 scraper for 2001–2025.** The
API it used returns the answer key, the HTML formatting, the images and the
passages. That would probably move most of the 4,001 `needs_key`
questions, plus the 3,666 `ai_key` ones, to `ready`. The 2000–2025 records
already keep the MySchool question id in `source_ref`, so re-scraped data
can be matched one-to-one.

## How far the AI keys can be trusted

The legacy `kairo.questions` bank was built by
`scripts/qim/generate_qim_batch.py`, which asked Claude to answer questions
from the keyless 2000–2025 files and write explanations. On the 261
questions that appear in both the legacy bank and the source-keyed
1978–2000 set (same stem and same options), **Claude's key matched the
source key 251 times (96.2%)**:

| ENG | BIO | PHY | CHM | MTH |
| --- | --- | --- | --- | --- |
| 98% | 100% | 97% | 94% | 95% |

That is good, but not good enough to label as "verified". About 1 key in 25
is wrong, so a 10-question daily quiz would contain a wrong key every two or
three days. Rules:

- Questions with `ai_key` can be used in practice, where the
  **Report this question** button catches errors.
- Daily quizzes and weekly drills use `ready` questions only, or `ai_key`
  questions that an editor has confirmed (`key_source = 'editor'`).

## Explanations

- Legacy explanations (Claude-written) exist for 3,664 questions, all in the
  `ai_key` tier, and they are linked through `explanation_legacy_id`.
- **None of the 5,878 source-keyed questions has an explanation.** For the
  pilot, generate explanations with the **source key given to the model**. If
  the model's own working disagrees with the source key, the question goes to
  the review queue. That check also catches the occasional wrong source key.
  The existing batch script can be adapted. At about 800 output tokens a
  question, the Batches API cost for all 5,878 is small, but it needs an
  Anthropic API key.
- The daily quiz needs only 10 questions a day, so explanations can be
  generated and checked a week ahead, a small set at a time.

## Flags (why questions land in `needs_review`)

| Flag | Count | Meaning |
| --- | --- | --- |
| `duplicate_options` | 809 | Two options read the same, usually because a superscript or fraction was lost (e.g. "kg m" / "kg m") |
| `diagram_missing` | 556 | The question mentions a diagram, figure or table but has no image, or the image is a placeholder |
| `passage_missing` | 370 | An English question mentions a passage that isn't included |
| `possible_lost_superscript` | 71 | Heuristic match on the question text (`x 2 -`); it misses some cases and flags a few false positives |
| `empty_option` / `option_count_3` / `short_stem` | 23 | Broken records |
| `image_not_hosted` | 561 | The source gives only an image file name. Blocking until the image is downloaded, compressed and stored by us |

## Before publishing

1. Download the 561 diagram images (the scraper knows the image base URL;
   the JSON stores only file names). Compress each one to under 60 KB and
   store it in our own storage (Supabase Storage or Cloudflare R2).
2. Content rights: JAMB past questions circulate widely, but these files
   were collected from MySchool's API, and their terms may restrict reuse.
   Keep only the question, options and key; write our own explanations;
   host our own images.
3. Tag each question to a syllabus topic using the existing taxonomy in
   `supabase/TAXONOMY.md` (a script suggests a topic and an editor confirms).

## Re-running

```bash
python3 -I tools/question-import/normalize.py --out /tmp/qb \
  --kairo kairo_export.json path/to/*.json
```

`kairo_export.json` is the saved result of the SQL query in the script's
docstring, run against the live project.
